Base: completed textarea branch `12.13.0-Textarea-Interactions` at

Authorized immediately after that branch on 31 October 2026.

## Historical review and approach

The historical `php9_compat` head is
`b5e1556ed2d3ab923f39ba7b4bfb005ded593fcc`, based on
`66619a48e1e00e5f51fb4d4c6f9d2ffa52ecced8`. Its parent already contained the
reverse-named mimic functions; the head replaced calls across 253 paths.
Those helpers were later removed from main by
`88038c48692c52e5d3ed6eff8539ea7e83a519af`. The count compatibility helper
remained. No historical branch is merged or cherry-picked here.

The old technique globally substituted aliases for native functions and made
null inputs silently look like strings or one-element lists. It also changed
HTML encoding defaults and failed to retain the output-reference parameter of
`str_replace`. This branch keeps native functions and gives their real callers
the appropriate data contract instead.

* `tnuoc` is removed. Current application code uses `count` on arrays produced by
  `explode`, `preg_split`, match arrays, upload collection helpers and explicit
  array initialization. Empty collections remain empty. Scalars do not acquire
  a pretend element count. The legacy benchmark adapts the old alias only inside
  its extracted historical source, where all benchmark inputs are arrays.
* Optional textual request/database fields use an explicit empty-string fallback
  at their text-consuming call sites. A token-aware migration inventory records
  the 746 affected argument boundaries in
  [12.14.0-text-boundaries.tsv](12.14.0-text-boundaries.tsv). These expressions do
  not change non-null values or turn arrays into strings. Database fetches retain
  SQL NULL: in particular search freshness, recovery rows and exact backups keep
  their null/empty distinctions.
* Query/cookie values used as text reject collection-shaped input at the request
  boundary. Missing keys are not globally invented; absence/isset semantics are
  retained. The search query remains under its dedicated request/parser policy.
* Rendering and identifier conversion establish empty-text and list contracts at
  their own entry points. Malformed address-list entries and failed IDN conversions
  are retained rather than being converted into a different identity.
* Removed `utf8_encode`/`utf8_decode` calls become explicit encoding conversions.
  Latin-1 conversions retain their original ISO-8859-1 intent; Windows-1252 and
  numeric-entity boundaries remain distinct. Existing source bytes are retained.
* CSV reads/writes specify RFC 4180 enclosure/doubled-quote escaping explicitly,
  fixing trailing-backslash round trips. The CSV reader retains an explicit
  legacy backslash option for old input.
  The import filename is now calculated after reading the actual CSV input,
  fixing the former hash of an undefined variable. Empty/malformed import input
  is rejected before processing.
* Obsolete GD destruction calls become object release through normal lifetime
  management. The database compatibility API checks liveness through a real query
  instead of deprecated `mysqli_ping`. It retains the existing public API.
* Bundled Composer dependencies are refreshed from upstream within the existing
  major-version constraints, with a clean installation that removes obsolete package files. Seventy-two native interface return contracts in 16 dependency files are
  declared explicitly instead of relying on `ReturnTypeWillChange`. Four void
  methods retain their advancement/removal side effects and stop returning a
  value. [The pinned patch manifest](../patches/php9-return-types.json) guards
  exact upstream and result hashes. Composer post-install/update hooks reapply
  these reviewed changes; unknown upstream versions stop for review. No reverse-name wrappers or new warning-suppression attributes are introduced. The lock file and distributable vendor tree travel together.

## Language-version scope

This work addresses published compatibility changes, including the planned
PHP 9 removal/error transitions. A future PHP release can introduce additional
changes; a claim of executed PHP 9 certification requires an actual PHP 9 runtime.
Use the exact observed runtime matrix below rather than interpreting the branch
name as that certification.

Primary specifications:

* https://wiki.php.net/rfc/deprecate_null_to_scalar_internal_arg
* https://wiki.php.net/rfc/remove_utf8_decode_and_utf8_encode
* https://www.php.net/manual/en/migration84.deprecated.php
* https://www.php.net/manual/en/migration85.deprecated.php

The updated dependency set raises the distribution's minimum PHP requirement to
8.2. The existing mail APIs and transport selection are retained; Composer reports
that the Laminas Mail/Mime/Loader packages are abandoned upstream. That maintenance
status is not hidden and no unsupported future-version certification is inferred
from Composer resolution. Mail/header/MIME behavior requires regression evidence.

## Validation checkpoint

The count/encoding changes passed the inherited 1,671 migration/database checks
on PHP 8.3.6. After explicit text-boundary normalization, the strict deprecation
router passed 159 textarea HTTP/browser checks and 475 main-diff browser checks.
These runs preceded the final upstream dependency refresh and must be repeated
on the final tree. The focused identifier, encoding, CSV and mail/MIME contract suite currently
passes 123 checks on PHP 8.3.6 and a source-built PHP 8.5.12. The final upstream dependency tree also passes the 159 textarea, 51 frontend, 98 backend and 475 main-diff checks on PHP 8.3.6. The final PHP 8.5 HTTP/image runs and search/OIDC acceptance regressions are in progress.

`tests/php9-guard.php` is a test-only prepend/router hook. It turns deprecations
into errors even where legacy bootstraps mask normal error-reporting categories;
it does not change production error handling. The real HTTP runner enables it
with `U5CMS_PHP9_AUDIT=1` instead of assuming CLI-server router requests honor
`auto_prepend_file` for included scripts.

Next action at this checkpoint: finish final-tree syntax/runtime and behavior
validation, resolve any remaining compatibility findings, update this report and

## Release and rollback

Keep application PHP, the matching Composer lock/vendor tree and the textarea
assets together. This branch introduces no automatic user-data re-encoding or
identity migration. Review custom PHP stored in site-specific P objects and
configuration: external code calling a removed alias or deprecated native API
cannot be certified by testing the repository alone. The release must use a
matching database/file backup and deployment-specific provider acceptance.
Rollback uses the complete prior branch files, lock and vendor directory.
Do not merge main or deploy a live CMS as part of these development tasks.
