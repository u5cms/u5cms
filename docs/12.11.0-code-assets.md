# u5CMS 12.11.0: typed code resources

The final `!` in a type C object's name separates the filename from its extension.
For example, `mobile!js` exports to `r/mobile.js`; `one!two!js` exports to
`r/one!two.js`. Ordinary page names and other resource types keep their meaning.

| Previous object | New object | Export |
| --- | --- | --- |
| cssbase | base!css | r/base.css |
| csslayout | layout!css | r/layout.css |
| cssstyle | style!css | r/style.css |
| cssform | form!css | r/form.css |
| csshot | hot!css | r/hot.css |
| cssnavleft | navleft!css | r/navleft.css |
| cssnavleftsubtop | navleftsubtop!css | r/navleftsubtop.css |
| cssnavtop | navtop!css | r/navtop.css |
| csstable | table!css | r/table.css |
| cssauthuser | authuser!css | r/authuser.css |
| cssupload (optional) | upload!css | r/upload.css |
| csspworder (optional) | pworder!css | r/pworder.css |
| htmltemplate | htmltemplate!html | r/htmltemplate.html |
| jsmobilespecific | mobile!js | r/mobile.js |
| jsmobilegeneral | mobilebase!js | r/mobilebase.js |

The four frontend upload script entrypoints return `text/javascript` with their
existing Windows-1252 encoding. Static code resources now have their actual file
extensions, so they work with `X-Content-Type-Options: nosniff` without a MIME
override in `.htaccess`. Server-side executable suffixes are not code resources.

The database and code editor keep the CMS's existing encoding. JavaScript and CSS
exports use UTF-8 with a BOM so both classic script loading and jQuery's local
script loader decode them consistently. JSON exports use UTF-8 without a BOM.
The HTML template retains Windows-1252 for the existing PHP rendering pipeline.
Entity strings are never HTML-decoded by the migration or exporter.

## Updating an existing installation

Upload the complete application update, including `codeassets.inc.php`,
`u5admin/codeassets-migrate.inc.php`, `u5admin/code-templates/`, and `r/runonce.php`.
As before, omit the other contents of `r/` when updating an existing site.
Then open the authenticated backend. Its `zr.php` runs `r/runonce.php`.

The update:

1. Runs the historical language/schema upgrade when required by an older schema.
2. Inspects existing code resources and their use. It guesses untyped custom
   resources from their content and script references; ambiguous content keeps
   the previous CSS behavior. The decision is recorded. Objects that already had
   a valid suffix keep their name, while their old `name!js.css` exports and
   references are migrated to the real suffix as well.
3. Plans every name, file and reference change before applying database changes.
   A collision receives a distinct name; existing objects are not overwritten.
   The currently used HTML template remains the active template even if its new
   preferred name is already occupied.
4. Saves a resumable checkpoint and backups of replaced/removed asset files in
   the existing protected `fileversions/` directory. The checkpoint contains
   the exact original and replacement database rows.
5. Publishes the new files, updates textual database references (including all
   languages, history and insert definitions), and re-exports from the database.
   Binary database fields are not rewritten. Database strings are read and
   updated as exact bytes, independently of their column charset.
6. Imports an existing local common mobile script where available; otherwise it
   installs the bundled `mobilebase!js` source. There is no runtime download from
   yuba.ch. Customized site-specific mobile code is retained.
7. Writes the completion marker, removes obsolete exports only after the new
   files and references are ready, and allows `runonce.php` to be removed.

Default source templates are kept in `u5admin/code-templates/`, outside the mutable
`r/` directory. They therefore survive the normal update procedure. Existing
database content is authoritative; the new defaults do not replace a site's
customized template, stylesheets or mobile code.

Absolute references such as `https://info.agov.ch/r/jsmobilespecific.css?...`
become `https://info.agov.ch/r/mobile.js?...`. The domain, installation subdirectory,
query and fragment are preserved. Both installations must receive the update.
The former yuba.ch code CDN URLs are changed to local resources; documentation
links to yuba.ch remain normal links.

If the earlier mobile MIME workaround is present, only that exact known block
is removed from `r/.htaccess`. Other local access/authentication rules are kept.

## Repeating or resuming an update

Re-uploading and rerunning this version does not rename the objects a second
time or duplicate the common mobile object. A successful repeated run refreshes
the generated files from the current database.

On a write or SQL failure, the update reports the error and retains `runonce.php`
and its checkpoint. Correct the reported problem and reopen the backend. It
resumes the existing plan, including after only part of the database was updated.
It does not re-run historical schema changes for an already modern installation.

An exclusive filesystem lock excludes a second updater or code rename while the
first is running. The lock is released automatically when its process exits.

A concurrent database edit is detected rather than overwritten. Keep the
checkpoint and the reported edited row for review; do not delete the checkpoint
to force an update. The original serving files are retained until completion.

The following protected files support diagnosis and recovery:

- `fileversions/codeassets-12.11.0.lock.php`: updater lock (the file can remain).
- `fileversions/codeassets-12.11.0.pending.php`: resumable plan, while unfinished.
- `fileversions/codeassets-12.11.0.done.php`: active template and final name map.
- `fileversions/codeassets-12.11.0-report.php`: classification/collision report.
- `fileversions/codeassets-12.11.0-files/`: original files wrapped in PHP exit guards.

## Regression checks

`tests/codeassets-regression.php` covers filename parsing, reference rewriting,
encoding, fresh installations, historical seed databases, customized code,
collisions, interrupted updates, retry behavior, publication failures, SQL
failures, concurrent edits, all five language fields, code renames, layout resets
with collisions, paginated data, and MyISAM/InnoDB installations.

Run it with PHP's mysqli extension and `U5CMS_TEST_PORT` pointing to a disposable
local MariaDB; `U5CMS_TEST_USER` defaults to `root` and `U5CMS_TEST_PASSWORD` to an
empty password. It creates and drops only random `u5asset_...` test databases.
The historical fixture uses commit `d8ce338a329062d5a00642643bfa958553b3dd42` from
this repository's history. `U5CMS_TEST_SITE_SOURCE` can optionally supply a real
site-specific mobile script as a private regression fixture.


```sh
U5CMS_TEST_PORT=3306 php tests/codeassets-regression.php
U5CMS_TEST_PORT=3306 python3 tests/codeassets-web-regression.py
```

The browser suite requires PHP with mysqli/mbstring, Node, Playwright, and Chromium.
It creates an isolated copy of the real CMS and a random disposable database,
serves every response with `nosniff`, and tests desktop, mobile, and shared-domain
loading. It exercises all four upload widgets with twelve real file uploads,
checks CSS application and JavaScript encoding, and verifies that mobile
conversion preserves form nodes, field values, and event listeners. Requests to
the former yuba.ch script CDN are rejected. External shared code is tested under
its original origin using locally served fixture bytes.

Set `U5_TEST_PHP`, `U5_TEST_PHP_ARGS` (a JSON array), `U5_TEST_BROWSER` (Chromium
executable), and `U5_TEST_PLAYWRIGHT` (module path) when those tools are not on
the default paths. The optional `U5CMS_TEST_SITE_SOURCE` fixture is also supported.

Validation for this release: 905 core/database assertions and 51 browser checks
passed using PHP 8.3, MariaDB 10.11, and Chromium 156, with no MIME or JavaScript
errors in the browser scenarios.
