# u5CMS 12.11.4: final collateral-damage review against production main

Baseline: main at `9d366253417822c279692767b89dcf1ff0388c5c`, verified against
GitHub on 26 October 2026. The reviewed release parent is 12.11.3 at
`049b10325f6cefb3444d3b3a4cad96836500d21d`. This release continues that ancestry;
main and the earlier release branches remain unchanged.

## Confirmed regression and correction

The code-resource rename had introduced a call to `u5CodeAssetPublicPath()` in
the HTML head of `sendintranetlogin.php`. That direct entry point loaded
`connect.inc.php` and the helper functions only later, in the body. Consequently
requesting an intranet password could fail with an undefined-function fatal
before reaching the existing password-order policy.

A subprocess comparison of the actual source prefix before the database
bootstrap established:

| Source | Exit status | Undefined helper |
| --- | --- | --- |
| Production main | 0 | No |
| Published 12.11.3 | 255 | Yes |
| Corrected 12.11.4 | 0 | No |

The sole functional application change is an explicit `require_once` of
`codeassets.inc.php` before the HTML document. It loads the pure helper functions
before the stylesheet lookup. The existing configuration/database bootstrap,
password-order policy, salt handling and mail flow stay in their original
positions. The new HTTP regression blocks password orders in its disposable
configuration, preventing mail/salt actions, and checks the actual entry point
with both `r/pworder.css` and the pre-migration `r/csspworder.css` path.

The other changed helper call sites were checked for initialization order.
Uploads load `myfunctions.inc.php` first; the main page and form-data endpoints
load `connect.inc.php`; backend pages load their backend connection; authuser
loads the login bootstrap; stylesheet publication explicitly loads its helper.
No other missing helper bootstrap was found in that review.

## Review scope against main

The complete changed-file inventory was inspected, including inherited backend
and image-upload changes, rather than limiting the review to 12.11.3's final
three-line authentication correction. Sensitive paths reviewed include:

* frontend/backend HTTPS configuration and login/permission checks;
* direct frontend entry points and typed stylesheet/template resolution;
* page/code/metadata saves, revision conflicts, preserved input and text history;
* resource new/copy/rename/delete behavior and publication of uploaded files;
* private download/thumbnail checks before conditional caching;
* SQL seeds, resource references, layout/reset baselines and upgrade bootstrap;
* SQL/ZIP backup publication, restore fidelity and failed-job cleanup.

The old SQL seeds and legacy `.tpl` fixtures used by the migration suite are
byte-identical to main at the baseline above (verified by Git comparison with
the fixture-source revision). They therefore exercise this production seed and
reset-template baseline. Custom-source/collision/history/encoding cases and
process interruption checks remain in that suite.

No migration/schema/SQL-seed/reset-template changes were needed in 12.11.4.
Existing 12.11.0/1/2 checkpoints retain their identities. Displayed application
and updater versions advance to 12.11.4.

literal entities, independent simultaneous page submissions, SQL/ZIP restore,
layout reset, private-file authentication/cache responses, thumbnail pixels,
album captions and repository scroll behavior. The Apache runs use two actual

legacy onchange/onkeyup-driven save button stayed hidden after automation's
fill/blur sequence. The caption test now enters text through keyboard events,
matching the existing user interaction, and the complete WebKit suite passed.
No album application code or visibility assertion was relaxed.

This review found and fixed one reproducible collateral regression. It did not
identify another actionable regression in the examined paths. These results
cover the stated fixtures and runtimes; they do not prove compatibility with
every custom deployment or external integration. HTTP 401/no-store on failed
private-file authentication remains an intentional change from main. WebKit is
not a physical Safari/iPhone test, and the container limitations documented in
the 12.11.3 report still apply. No production installation was changed.
