# u5CMS 12.11.3: process termination and web-server regression

This maintenance release follows 12.11.2 at
`9b3bb2879e19744502b1d8334b556fa8ad8cbe26`. It keeps the existing release
ancestry, including the earlier backend and image-format work. The nine remote
branches present before publication were checked; main and php9_compat were
not merged or modified.

## Application correction

A failed private-file login in session mode previously returned an HTTP 200
JavaScript login redirect. In the full Apache/PHP-FPM regression, an anonymous
conditional thumbnail request consequently received HTTP 304. Instrumentation
confirmed the authentication branch exited with HTTP 200; a small standalone
PHP/Apache probe did not reproduce this by itself. The full CMS regression
reproduced the issue and passed after the targeted correction.

The shared private-file authentication guard now returns HTTP 401 and
`Cache-Control: no-store` before either login response. Basic authentication
keeps its challenge; session authentication keeps its existing JavaScript login
redirect. Successful authorized downloads and their conditional responses are
unchanged. The explicit configuration that skips intranet login is unchanged.
The regression requires 401, no-store and a non-image response for an anonymous
conditional thumbnail request.

No additional migration, schema, SQL-seed, code-template or reset-baseline
changes are introduced in this release. Existing 12.11.0/1/2 immutable
migration checkpoints retain their versions. The existing updater runs them
when needed and reports the installed application version as 12.11.3.

## Additional regression coverage

* Seven separate PHP workers are terminated with OS SIGKILL at `planned`,
  `templates-written`, `files`, `row:0`, `database`, `exported` and `complete`.
  The parent verifies signal 9, resumes the migration, checks its database and
  exported assets, then verifies a further run leaves database bytes unchanged.
  These complement the existing exception, collision and concurrent-edit tests.
* Two independently authenticated browser contexts submit the same page
  revision concurrently. Exactly one conflicts, one complete source remains
  current, and both inputs remain recoverable in text history. Both Basic and
  cookie authentication are exercised.
* The browser suites can select Chromium, Firefox or WebKit through
  `U5_TEST_ENGINE`. A legitimate save-and-close is accepted alongside a form
  revision acknowledgement; the database source and object type are still
  checked. Repository highlighting is checked in the iframe's actual DOM,
  avoiding Firefox automation's stale navigation identity after the legacy
  editor uses document.open/write.
* `U5_TEST_SHARED_ORIGIN` permits an actual second local server origin. Without
  it, the existing self-contained shared-domain response fixture remains
  available. The additional Apache runs used two HTTP origins, real files and
  `nosniff`, without fulfilling the cross-origin script responses in Playwright.
* The old-parser reproduction subprocess inherits the configured PHP arguments.
  PHP 7.4 loads JSON as a module, whereas the PHP 8 test runtime includes it.

Counts vary with optional ZIP coverage and the web server: the missing-ZIP
failure path adds two checks, stress adds six, and real Apache authentication
changes which redirect/response branches are exercised. Each listed run passed
its complete configured suite. The stress worker again peaked at 6 MiB under a
64 MiB limit, with 2,500 large rows, 5,000 history rows and a 4.2 MB BLOB.

The browser runs include Unicode/entity preservation, uploads, real backend
forms, Basic/session authentication, SQL/ZIP restore, layout resets, permissions,
thumbnail dimensions/pixels and cache checks, queued/failing saves and scroll
behavior. The existing 12.11.2 image-format validation remains applicable;
image decoders were not changed in this release.

The Apache fixture uses Apache 2.4.58, PHP-FPM 8.3.6 and four workers, with real
Basic directory protection and MIME configuration. It runs in the local test
namespace as its existing user; Unix privilege dropping and production hosting
configuration are not covered. WebKit 26.5 is a browser-engine test, not a test
on a physical Safari/iPhone installation. Firefox 153 requires its content
sandbox disabled in this restricted test container; that setting is explicitly
opt-in through the test launcher and does not affect CMS configuration.

All database and web fixtures in this release round are disposable synthetic
installations. No production update was performed. A whole live database/files
backup during arbitrary concurrent writes is not claimed to be an atomic
snapshot. The OS-kill checks cover the named checkpoints, not every possible
instruction or power-loss/filesystem failure.
