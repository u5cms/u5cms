# DynaForm and attachment teaching checks

[Documentation laboratory](README.md) · [DynaForm tutorial](../dynaform.md)

## Scope

On 28 November 2026, the complete page sources supplied with the room-handover tutorial were installed in a disposable copy of stable u5CMS 12.10.16, source commit `0e704d9d78e80c1d82892966b2e7dd740cea5787`. The local runtime used PHP 8.4.27, MariaDB 11.8.9 and Chromium Headless Shell 156.0.8078.79. The fixture used the repository's schema, actual renderer, native form-save and edit handlers, and real database records. Browser requests to other hosts were blocked.

The designer was an existing backend account. Bob and Clara were ordinary page readers, absent from the backend accounts table. Credentials were generated for the disposable installation. No production application, reference application's records or live mail transport was changed by these checks.

## Observed paths

| Printed example | Observed result |
| --- | --- |
| Three room-question definitions | Created through the supplied configuration form, stored under `df!room!edit`, listed and rendered in position order. |
| Required answers and designer access | Empty required answers stayed on the answering page. A page reader received HTTP 401 for the designer list. |
| Save and reopen | Room, SELECT code and notes survived a native save and MF prefill. Notes containing a semicolon, apostrophe, ampersand and umlaut returned correctly. |
| Revision and retained history | The second save left one current answer under status 1 and one former answer under status 6. |
| Reader separation | Clara started empty and did not receive Bob's saved output. A signed-out request for the output received HTTP 401. |
| Change a definition | The native Edit link loaded the definition. A label change preserved the saved SELECT value. A newly added optional key-count question appeared empty beside the existing answers and then saved as `2`. |
| Second form family | `df!kit` used the same shared components; its equipment definitions and answer remained separate from `df!room`. |
| MF prefilling hook | The complete `timepreference` script showed the note after restoring Town hall, hid it on Library input, and kept it hidden after saving and reopening. |
| Two attachments | Native uploads produced two protected links whose downloaded bytes matched their separate test payloads. A text-only revision preserved both. Clearing and replacing the second widget changed only the second download. Signed-out and unauthorised page-reader requests for the backend-only example were denied. |

All eight DynaForm component sources also passed PHP syntax checking. Changed Markdown files passed checks for balanced fenced code and existing relative file-link targets.

## Repeat and interpret

Follow the tutorial's exact object manifest and its steps 2–8 on a practice installation. Use separate browser profiles for the backend designer and the two page readers. Compare the visible values with the expected results after each step; inspect current and former records through **Form data**. Repeat the separate [two-attachment exercise](../forms/uploads.md#build-a-two-attachment-example) with two small, recognisable PDFs and open the actual downloaded documents.

These checks establish the supplied teaching components' local behaviour. They do not certify a site's private composer, custom access integration, identity provider, live SMTP service, upload policy or retention configuration. The library deliberately supports the two named example families; extending it is an explicit administrator task described in the tutorial.
