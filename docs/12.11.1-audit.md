# u5CMS 12.11.1: migration audit

12.11.1 follows commit `43ee1e3e1ebc3c0b56b362c60c059447f5cf3641` on
`12.11.0`. Its ancestry retains `12.10.1-Support-More-Image-Formats` and the
preceding backend fixes. It does not start again from `main`.

The second audit reproduced additional failures in 12.11.0. These were corrected
and added to the regression suite before publishing this patch.

## Reproduced failures and corrections

- A field containing references to 600 distinct C resources could exceed the
  generated regular-expression limit and become an empty string. Reference
  matching now uses constant-size patterns and lookup tables. Regex failures
  throw an error instead of returning an empty replacement.
- CSS imports starting with `./`, percent-encoded exclamation marks, encoded
  resource queries, and media-proxy wrappers could retain obsolete paths.
  These forms now follow the final typed filenames. Hosts, installation paths,
  query strings, fragments, and encoded components are preserved.
- Already typed mobile CDN paths could still load from yuba.ch. Known old and
  new code-CDN paths now resolve locally. Absolute external URLs are excluded
  from export cache-version additions, preserving signed URLs.
- Quoted DOM identifiers, JavaScript array access, CSS selectors, JSON bindings,
  and built-in template slots could be mistaken for C references. Rewriting now
  distinguishes source formats and markup/code contexts. Explicit CMS includes,
  actual asset paths, resource URLs, and embedded CMS HTML still migrate.
- Modern JavaScript and HTML fragments could be guessed as CSS. Detection now
  recognizes modules, classes, more script syntax, HTML fragments, and BOMs.
  Ambiguous legacy C sources retain the CSS fallback and receive a report entry.
- Non-Latin1 code could be lost through the legacy database connection, editor,
  copying, or history. Code and code-metadata editors now submit UTF-8 and render
  raw Unicode safely. Exports read raw UTF-8 directly from the database. Writes
  check charset round trips, rejecting unrepresentable input before changing
  the source. SVG/XML declarations match their exported UTF-8 bytes.
- The administrator permission include reused the resource row variable during
  saving. Code and metadata saves now retain their own resource snapshots,
  preserving the correct revision and type across permission checks.
- Large changed-text/history collections could exhaust PHP memory while building
  a single plan. Rows now stream into bounded guarded backup blocks, with hashes
  and manifests. Recovery accepts both the older list format and these blocks.
  Opaque binary fields stay untouched and are compared by server-side hashes.
- Generated columns and automatic update timestamps could prevent updates or
  recovery. Generated columns are excluded from assignments; automatic
  timestamps remain database-managed. A history lookup index avoids repeated
  full-history scans. History text widths and Unicode capacity follow the source
  while preserving column defaults and comments.
- Targets could collide with independent files or directories. Planning reserves
  existing filesystem names and assigns distinct mapped targets. Long-name
  collision suffixes stay within the filename limit. Current P names and
  historical C names are handled separately. Retained exports of deleted or
  history-only C objects keep their actual contents without reactivating them.
- Updated references previously retained their old editor revision. Changed
  resources now receive a new revision and cleared search cache, so stale
  editors encounter the configured conflict protection.
- Code creation, copying, renaming, archiving, deletion, metadata saves, resets,
  and export now cooperate with the updater lock. Copying uses SQL directly to
  preserve source bytes, also copies the reset baseline, and creates no empty C
  media directory. New/reactivated code exports immediately. Deletion respects
  the keep-files option and removes flat exports/templates when requested.
  Previous states are preserved in history before deleted-state rows collapse.
- Typed names with dashes could be stripped by sanitizers or naming forms.
  Valid typed C names now retain those characters through the relevant routes.
  Code-save endpoints verify the actual resource type. Metadata requests cannot
  change the resource type through their URL.
- Real MySQL testing exposed numeric comparisons that interpreted raw hexadecimal
  literals as numbers, charset deprecation notices mistaken for conversion loss,
  and native JSON normalization affecting recovery. Numeric values now have
  explicit character context; exact charset round trips distinguish actual loss;
  native JSON values use UTF-8 and compare their database-normalized form.
- The older schema updater used MariaDB-only conditional ALTER syntax. Its
  conditional column/index changes now check metadata and issue portable DDL.
  A complete three-language `_d/_e/_f` fixture, missing tables, and missing
  language columns now upgrade on both databases.

## Existing installations and reset baselines

Upload the complete application update and only `r/runonce.php` from the
distribution's `r/` directory. Keep the site's other existing `r/` files.

The original 12.11.0 migration/checkpoint identifiers remain compatible. An
unfinished older plan finishes first. An installation already marked complete
receives a separate 12.11.1 reference/reset-template repair using its existing
role mappings, including subsequent manual code renames. A repeat run leaves
resource rows unchanged and refreshes exports from the database.

Reset sources stay under `r/`: for example, `cssbase.tpl` becomes `base!css.tpl`.
Customized sources and their dependencies are preserved. The update does not
apply a reset to the live layout. Explicit resets use those preserved sources,
advance revisions, and save previous contents in history and guarded row backups.
No `u5admin/code-templates/` directory is introduced. No MIME `.htaccess`
workaround is shipped; only the exact older mobile workaround is removed from
an existing `r/.htaccess`, retaining unrelated access rules.

The protected `fileversions/` backups retain original/replacement row blocks and
original asset/template bytes. Subsequent distinct file versions are retained
alongside the initial compatibility backup. Keep pending journals and their
referenced blocks together when resuming an interrupted update.

## Executed verification

All suites passed with PHP 8.3.6 and Chromium 156.0.8078.47:

| Suite | Environment | Result |
| --- | --- | --- |
| Core, database, migration, failure/recovery and stress assertions | MariaDB 10.11.14, MyISAM and InnoDB | 1351 passed |
| Same core/database/stress suite | MySQL 8.0.46, MyISAM and InnoDB | 1351 passed |
| Real frontend with `nosniff`, desktop/mobile/shared origins and 12 actual uploads | MariaDB | 51 passed |
| Real backend forms, iframe saves, Unicode, revisions, CSRF and C lifecycle under Basic and session authentication | MariaDB | 98 passed |
| Same frontend and backend browser suites | MySQL | 51 + 98 passed |
| Inherited image-upload/archive/failure browser regression | PHP GD and Chromium | 94 passed; 33 output images inspected |

The stress worker migrated 2,500 text rows of about 16 KB each, 5,000 history
versions, generated references, and text beside a 4.2 MB opaque BLOB under a
64 MiB PHP memory limit. Its measured peak was 6 MiB on each database.

Migration coverage also includes both installation SQL dumps, customized code
and reset baselines, physical and resource-name collisions, 220-character names,
all five language fields, the older three-language schema, preview recovery,
completed-release repair, old list checkpoints, interrupted row/template/file
phases, damaged blocks, concurrent writes, and repeated execution. Constrained
VARCHAR/TEXT/ENUM/SET values and exhausted 32-bit integer revisions fail during preflight
instead of silently truncating changed values. PHP syntax and diff whitespace
checks also pass for the changed sources.

The shared-origin browser scenario serves updated local fixture bytes under the
`info.agov.ch` origin. It tests the requested assumption that both installations
receive the update; it does not deploy to or alter that production service.

## Practical limits

The tested configurations pass; this is not a guarantee for every private
extension, SQL mode, webserver configuration, or database trigger. Custom schema
constraints that cannot represent a replacement stop the migration with an
explicit error. Resolve the reported constraint and retry with its checkpoint.

The migration recognizes stored paths, URL/query forms, supported serialization,
CSS imports, and CMS inclusion syntax. It cannot reliably infer arbitrary names
assembled dynamically by custom programs. Unknown C types are classified from
source/use and reported for review.

If an earlier 12.11.0 run already erased arbitrary text or changed unrelated
program identifiers, a patch cannot infer the missing original contents. Recovery
of that prior damage requires the earlier database/history/file backups. 12.11.1
prevents those reproduced failures and preserves its own original row blocks.

See [the migration guide](12.11.0-code-assets.md) for installation and test commands.
