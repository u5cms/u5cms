# u5CMS 12.12.0: OIDC implementation and validation

Release date: 30 October 2026. Branch: `12.12.0-OIDC`.
Base: `feature/search-phrases-quotes-highlighting` at
`2f5ce37c18b017375dfc31dab6086f325bd836a2`. That branch includes the cumulative
12.11.4 migration, backend, upload and search work. Production `main` remains at
`9d366253417822c279692767b89dcf1ff0388c5c` and is not modified or deployed.

## Result and integration review

OIDC is an opt-in federation option, with the existing local and SAML paths
retained. The supported protocol/security profile and deployment instructions
are documented in [oidc.md](oidc.md). The review traced configuration and all
authentication entry points, not only the SAML assertion receiver:

* Root/backend connection bootstraps, local login saves and login forms;
* frontend yes/no policy, literal substring exception and always-federated
  backend/backend previews, including original URLs before HTML escaping;
* independent local frontend credentials and OIDC backend sessions;
* backend account and higher-admin checks, intranet and page-group permissions,
  private downloads/thumbnails, search/form saves and upload attribution;
* invitations, password changes/recovery, login information and nonmember text;
* automatic intranet enrollment and normal permission/file publication;
* local and RP-initiated logout, configured result page, attributes and test mode;
* CMS-native username encoding, internationalized email and exact issuer/subject
  bindings without email-claim privilege elevation in the default profile.

Existing account passwords are not overwritten. The optional verified-email
profile requires an explicit setting, signed verification claim and durable
unique identity bindings. The default profile uses only explicit subject maps.
Enrollment reuses the existing intranet/private-file publication workflow,
serializes enrollments and retains a pending marker if publication is interrupted.

Five legacy backend entry points emitted HTML before authenticating. Their
connection/authentication bootstrap now runs first so OIDC works without output
buffering, and unauthorized requests do not produce those pages' initial output.
Their normal content and data operations are retained. No root mail dependency
was upgraded. The isolated JWT package is pinned to 7.2.1, with its licence and
Composer lock file included.

## Reproducible checks

Use PHP with the listed extensions, Python with cryptography/Pillow, Node with
Playwright and a **disposable** local MariaDB server. The database fixtures create
randomly named databases and remove them at completion. No production CMS or
provider account is used. Set `U5CMS_TEST_PORT`, and where needed
`U5CMS_TEST_USER`/`U5CMS_TEST_PASSWORD`; the test account needs permission to
create and drop these test databases.

```sh
php tests/oidc-regression.php
php tests/oidc-bindings-regression.php
python3 tests/oidc-web-regression.py
```

`U5_TEST_PHP` selects a PHP executable/wrapper; `U5_TEST_PHP_ARGS` is a JSON array
of its additional arguments. `U5_TEST_PLAYWRIGHT` selects the Playwright package
and `U5_TEST_BROWSER` the Chromium executable. Set `U5_OIDC_HTTP_ONLY=1` to run
the complete HTTPS endpoint suite without launching a browser. The regular run
includes both; a browser failure is not silently skipped. The OIDC fixture
defaults to `output_buffering=0` and runs a real TLS provider and CMS TLS proxy
on distinct local ports, including a CMS subdirectory. The PHP backchannel uses
the generated CA and performs real TLS, PKCE and client authentication.

The core tests cover valid signed tokens and wrong/missing/expired claims,
algorithm confusion, bad signatures, untrusted JOSE headers, key ambiguity,
discovery origin/issuer/capabilities, exact return URLs, client authentication,
PKCE, state/nonce, replay/cancellation, parallel-tab transactions, session ID
rotation/fixation, absolute/idle expiry, configuration changes and logout races.
Database tests cover stable bindings, issuer/client separation, native bytes,
email recycling, concurrent first logins, idempotent installation and invalid
uniqueness constraints. The HTTPS tests additionally exercise the actual CMS
permission and lifecycle paths above, TLS rejection, provider failures, key
rotation, literal frontend exceptions, enrollment, verified-email linking and
internationalized identifiers. They assert no access-token persistence or secret
logging. The SAML regression uses its existing mock assertion path; it is not
a live SimpleSAMLphp/IdP interoperability certification.

Observed runtime: PHP 8.3.6, MariaDB 10.11.14, Chrome Headless Shell 156.0.8078.79
on Linux. The browser uses the same Chromium rendering/HTTP/session engine with
an isolated profile; these are not physical Safari/iPhone or production IdP
tests. The local host disallows native Unix-domain sockets, so the headless
shell is used in place of desktop Chrome's profile-singleton process.

Additional implementation details verified include original password/rights
preservation, immediate local permission removal, actual CLI setup, original
SAML policy inheritance and explicit OIDC overrides, one-time logout state,
local frontend cookies surviving backend federation, and no privileged account
creation through enrollment. The verified-email cases include recycled/changed
email rejection, explicit administrator-address reservation and an end-to-end
internationalized username through native intranet authorization.

All tests use disposable local data. A real eIAM/AGOV or other production client
registration and its exact provider policies still require deployment-specific
acceptance. The historical SimpleSAMLphp implementation itself is unchanged;
its external library/provider interoperability is not newly certified here.
